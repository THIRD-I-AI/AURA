## 2. Process changes since you were last here
- **CI is required to merge.** Ruleset "Require CI on main" lists 17 checks (backend tests 3.11/3.12, lint,
  migrations, frontend type check/lint/tests/render smoke, heal accuracy, SDK sync, streaming, causal, scheduler, S3,

  Merge with `gh pr merge <n> --auto --merge`; never `--admin`.

- **Stacked PRs are the norm** for dependent work: the base is the PR below it. Merge bottom-up, then retarget
  the next PR to `main` (`gh pr edit <n> --base main`).

## 3. Rules that matter
- **Bug registry** (`docs/BUG_REGISTRY.md`): numbers up to **BUG-599 are taken** (some by open PRs). Start new entries at
  **BUG-600**. The file is CRLF: edit it byte-safely and check `git diff --ignore-cr-at-eol --numstat`.
  Each entry: status, found by, severity, root cause with file:line, failure scenario, fix.
- **DuckDB and tenant data (security).** Any DuckDB connection that touches tenant-supplied files or SQL must come from
  `shared/duckdb_factory.new_connection()` and be passed through `lock_down_connection()` before user SQL runs.
  A tenant-supplied database file must be a real DuckDB file (`require_duckdb_file`). See BUG-189, BUG-595, BUG-597.
- **Secrets.** The production `.env` was rotated on 2026-11-27 (`SECRET_KEY`, `AURA_CREDENTIAL_ENCRYPTION_KEY`), so
  tokens issued before that are invalid. A disaster-recovery copy of `.env` lives in AWS SSM Parameter Store and is
  refreshed on every deploy by `deploy/aws-free-tier/env-backup.sh`. Never commit `.env`.
- **Backups.** Nightly at 03:15 as `ec2-user` (never root), with an offsite S3 copy; `/health` reports `ops.backup`
  and the live check `backup_fresh` fails when it is not `ok`. Restore has been drilled end to end (BUG-593).
- **Live verification.** `scripts/verify_live_deployment.py` (needs a `verify_` account) must pass after a deploy.
  Test data it leaves behind is removed with `scripts/cleanup_verify_resources.py`.
